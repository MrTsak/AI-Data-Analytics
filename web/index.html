      How it was tested

      • The data: 100,000 records. 3,854 exact duplicates and 18 records with gender "Other" were removed, leaving 96,128. The records were split 80/20, stratified so both sets keep the same share of diabetic records.
      • The models: a random forest (150 trees, depth 7) and a logistic regression, both trained on the training set only. Missing values were filled with training-set averages, so the test set never influenced training.
      • Scoring: ROC-AUC picks the best model, because only 8.8% of records are diabetic and accuracy alone can look high while a model misses cases. Recall, precision and F1 are reported at a 0.5 cut-off.
      • Checks: the pipeline has automated tests. The browser predictor matched the Python models on 200 test inputs to within one part in a million.
      • What it cannot show: the records have no lifestyle, diet, family-history or genetic data, and their origin is not documented. Nothing has been validated clinically or on another population. This is a teaching tool, not a diagnosis, and neither model is suitable for screening.

      Findings and limitations

        Built by Ioannis Tsakalidis. Originally a CustomTkinter desktop app for a Gatehouse Awards qualification, then rebuilt for the web. The Python pipeline, tests and the original desktop version are on GitHub.

        Data: the Diabetes Prediction Dataset by iammustafatz, published on Kaggle. Licence on Kaggle: “Data files © Original Authors”. The page shows only summary results and models trained on the data, not the records. The dataset’s origin is not documented, so treat the results as illustrative.
